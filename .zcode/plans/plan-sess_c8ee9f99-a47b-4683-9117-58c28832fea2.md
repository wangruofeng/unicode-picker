发布 `unicode-symbol-picker` 到 GitHub 公开仓库并部署到 GitHub Pages（自定义域名 `unicode.wangruofeng007.com`，域名根路径）。

## 决策摘要
- 仓库名：`unicode-symbol-picker`（公开）
- 部署：GitHub Pages + 自定义域名 `unicode.wangruofeng007.com`（域名根路径，非子路径）
- 用户负责 DNS 配置（CNAME 指向 `wangruofeng.github.io`）

## 实施步骤

### 1. 更新硬编码域名 `unicode-symbol-picker.wangruofeng007.com` → `unicode.wangruofeng007.com`
共 7 个文件（已审计确认，根相对路径无需改动）：
- `astro.config.mjs:4` — `site`
- `src/pages/index.astro:16,21,30` — canonical / og:url / JSON-LD
- `src/pages/category/[slug].astro:20` — canonical
- `src/pages/block/[slug].astro:18` — canonical
- `src/pages/symbol/[codepoint].astro:25` — canonical
- `public/robots.txt:4` — Sitemap 声明
- `scripts/build-search-index.mjs:85-88` — sitemap URL 生成（改后需重跑生成 `public/sitemap.xml`）

**保留不动**：`emoji-picker.wangruofeng007.com`（姐妹站外链）、`github.com/wangruofeng/unicode-symbol-picker`（GitHub 链接）。

### 2. 添加 GitHub Pages 部署文件
- 新增 `public/CNAME`，内容 `unicode.wangruofeng007.com`（Astro 会把 `public/` 内容复制到 `dist/` 根，GitHub Pages 据此识别自定义域名）。
- 新增 `.github/workflows/deploy.yml`：Astro 官方 GitHub Pages 部署工作流
  - 触发：`push` 到 `main`、手动 `workflow_dispatch`
  - 权限：`contents: read` + `pages: write` + `id-token: write`
  - 步骤：checkout → setup Node 20 → `npm ci` → `npm run build` → 上传 `dist/` artifact → 部署到 GitHub Pages
  - 并发组：`pages`，取消旧运行

> **注意关于数据生成**：`public/data/17.0.0/` 体积大（catalogs ~5.4MB + 201 个 block/category/detail 分片）但 **已提交进仓库**（`.gitignore` 只忽略 `data/ucd/` 和 `data/generated/`，不忽略 `public/`）。因此 CI 只需 `npm ci && npm run build`，无需重跑数据下载/解析管线（那需要下载 UCD 并用 Node 解析）。这是最简且最可靠的方案。

### 3. 添加 LICENSE、README
- 新增 `LICENSE`：MIT（与姐妹项目 emoji-picker 一致，用户惯用）。
- 新增 `README.md`：项目简介、特性、本地开发、数据构建命令、部署说明（GitHub Pages + 自定义域名 DNS 配置指引）。

### 4. 更新 `.gitignore` 审计
当前 `.gitignore` 已正确忽略 `node_modules/`、`dist/`、`.astro/`、`data/ucd/`、`data/generated/`、`.DS_Store`。`public/data/` **不忽略**（提交，CI 直接 build）。无需改动。

### 5. 重跑数据构建生成最新 sitemap
由于步骤 1 改了 `build-search-index.mjs` 的域名，需运行 `npm run data:index`（即 `node scripts/build-search-index.mjs`）重新生成 `public/sitemap.xml`，确保提交的是新域名的 sitemap。

### 6. 初始化 git 仓库并推送
- `git init` → `git branch -M main`
- `git add -A` → 初始 commit
- `gh repo create wangruofeng/unicode-symbol-picker --public --source=. --remote=origin --push`（用 gh CLI 一步创建公开仓库并推送）

### 7. 启用 GitHub Pages
- `gh api -X POST repos/wangruofeng/unicode-symbol-picker/pages -f build_type=workflow`（配置 Pages 使用 GitHub Actions 部署）
- 等首次 Actions 运行完成后，在仓库 Settings → Pages → Custom domain 填入 `unicode.wangruofeng007.com`（或用 `gh api` 设置）。**Enforce HTTPS** 建议开启。

### 8. 提示用户完成 DNS 配置
GitHub 侧配好后，用户需在 DNS 服务商添加：
- `CNAME unicode → wangruofeng.github.io`（推荐，或用 A 记录指向 GitHub Pages IP）
- 等 DNS 生效后，访问 `https://unicode.wangruofeng007.com/` 验证。

## 风险与回退
- **首次部署失败**：会展示 Actions 日志排查（常见：Node 版本、依赖缺失）。
- **DNS 未配置**：部署成功但自定义域名 404，可通过 `https://wangruofeng.github.io/unicode-symbol-picker/` 临时访问（注：因 CNAME 文件存在且为根路径配置，此备用地址在自定义域名生效前可能重定向，属正常现象）。
- **不创建** `wangruofeng.github.io` 用户主页仓库（会占用，且非用户选择）。

## 验收标准
- 公开仓库 `github.com/wangruofeng/unicode-symbol-picker` 创建成功
- GitHub Actions 绿色，Pages 部署成功
- `https://unicode.wangruofeng007.com/` 在用户完成 DNS 后可访问（部署本身不依赖 DNS）
